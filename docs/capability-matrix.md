# Capability Matrix — what benzene-go does, deliberately doesn't, and how to fill the gap

Benzene is honest about its boundaries. This page is the single place that states, for each
package or area of this port, **what it provides** (with the code that provides it), **what it
deliberately does not do (and why)**, and **how to solve the rest outside Benzene**. A gap that is
a design decision is stated with its reasoning; a gap that is simply unbuilt says "not
implemented" plainly — the two are never conflated here.

## The one idea behind every row

Benzene abstracts at the **business-logic boundary** — you write a message handler once and host
it anywhere — and **never at the transport or storage boundary**. If you wrap SQS behind a
generic queue interface, you lose the SQS-specific capabilities that were the reason to choose
SQS. So Benzene's answer to "does it abstract X?" is usually a deliberate **no**: every binding
exposes the native message/event, and rolling your own middleware is a first-class, supported
path, not an escape hatch.

Two corollaries specific to this port:

- **The root module is zero-dependency.** Every third-party dependency lives in its own Go module
  (`awssqs`, `kafka`, `grpcbinding`, …) so importing the core never pulls an SDK you didn't ask
  for. A "needs an SDK" boundary below is that policy, not a missing feature.
- **A database is not a transport.** Benzene delivers events *in*; persisting state is your
  handler's own code with its own SDK/driver.

## Core

| Capability | What benzene-go provides | What it deliberately does NOT do (and why) | How to solve the rest |
|---|---|---|---|
| **Pipeline & routing** | `Topic`, `Status`, `Result[T]`, `Registry`, `Middleware`/`Pipeline`, `RouterMiddleware`, three-phase `App` lifecycle (root module: `app.go`, `router.go`, `registry.go`, `middleware.go`) | Reflection/attribute-scanning handler discovery — this port is explicit-registration by design (`core-concepts.md` §8's "explicit registry" idiom for Go) | Register handlers explicitly on the `Registry`; the compiler is your discovery mechanism |
| **DI** | DI-lite `Container`/`Scope` + `ScopeFromContext` (`scope.go`) | Ship or integrate a reflection-based DI container — Go has no DI-container culture to bridge to | Constructor wiring in `main`; the `Container` covers per-invocation scoping |
| **Wire envelope & reserved names** | Transport-neutral envelope, `ResolveMetadataTopic`, `ReservedNames` — one injectable value for the configurable `topic`/correlation/version keys of `wire-contracts.md` §2 (`wire/envelope.go`, `wire/metadata.go`) | Impose the envelope on transports that already carry routing (EventBridge `detail-type`) — the native key *is* the routing key there; Kafka and RabbitMQ read the `topic` header first and fall back to their native key (Kafka topic, routing key) | Envelope-less transports use the Benzene envelope or a preset topic; otherwise route on the native key |
| **Versioning** | Version selection per `core-concepts.md` §2 (`router.go`, `registry.go`, `router_version_test.go`): the version comes from the one `benzene-version` header (`wire.DefaultVersionKey`; renamed in one place via `ReservedNames.VersionKey`, which `UseDefaultPipeline` passes as `WithVersionKey`) or an HTTP `{version}` route segment (sugar for the header). A versioned message runs the exact `(id, version)` handler or is `not-found` naming topic and version; an unversioned one runs the topic's default handler — the unversioned handler, else the one registered with `benzene.AsDefault()`. A topic with only versioned handlers and no declared default is logged as a warning when the router is built (`Registry.TopicsWithoutDefault`). A `version`/`x-version` header is an ordinary header | Transparent payload up/down-casting (`versioning.md` §4 Mechanism B) — **not implemented**: spec-optional, and the .NET implementation leans on reflection this zero-dependency port avoids; so the spec's cast-reachable selection step never applies. No "highest available" selector, even as an opt-in. Outbound clients do not write `benzene-version` from `Topic.Version` — **not implemented** | Register a handler per supported version and declare the oldest one default; set the `benzene-version` header yourself on an outbound send; do payload up-casting in a small middleware if you need it |
| **Validation** | `Validated(validator, handler)` typed handler wrapper + `Validator[T]`/`Combine` (`validation/`); `validation.Pointer` builds the RFC 6901 JSON Pointer each `errors[].field` carries (`wire-contracts.md` §1.3), from the request's JSON names (`json` tags) — runs the `conformance:validate` case | A struct-tag/reflection validation DSL — the pipeline is type-erased until dispatch, so validation is a typed wrapper, not a pipeline middleware; and the wrapper cannot check a validator's `Field` is a pointer (the validator writes it) | Plug any validation library inside your `ValidatorFunc`, converting its property paths with `validation.Pointer` |
| **In-process dispatch** | `inprocess` — an in-process `client.Sender` over named pipelines (`PipelineSet`), for the modular-monolith pattern | A container-wide outbound routing table (the .NET/TypeScript shape) — this port has no process-wide registry to hook into; a `Sender` is constructed and used directly like any other client | Construct the in-process `Sender` in `main` and pass it where a transport client would go |
| **Outbound error fidelity** | Every client that can receive a problem document rebuilds the Result's `errors` from it with `message`, `field` and `code` intact (core-concepts §12): `httpclient.Client` — from the failure envelope (`envelope.ToResult`, `errors` else `detail` as one opaque error) and, when the response is not an envelope, from an `application/problem+json` (or JSON) problem body, the status then from the reverse HTTP table; `awslambdaclient.Client` — from the failure envelope (`envelope.ToResult`); `inprocess.Sender` — no wire, the handler's errors are passed through whole. Run end to end against `problem-details-cases.json`'s `envelopeCases` by `conformance/client_fidelity_conformance_test.go` (httpclient over the envelope endpoint and over a route-mapped problem+json response, inprocess) and `awslambdaclient/problem_conformance_test.go`. The one-way clients (`awssqs`, `awssns`, `awseventbridge`, `gcppubsubclient`, `azureservicebus`, `azureeventhub`, `azureeventgrid`, `azurequeuestorage`, `rabbitmq`, `kafka`, `awsstepfunctions`) receive no reply and answer `accepted`: there is no request-reply queue client in this port. `grpcbinding.Client` reads the gRPC error model of wire-contracts §4.2 rather than a problem document: `field` survives (from `BadRequest.FieldViolation.field`, turned back into a pointer) and so does `code` (from `FieldViolation.reason`, §4.2) | Attach the received problem document verbatim (the MAY of §12) — an application's own problem `type` reaches the caller only as the status and errors | Read an application-defined problem `type` at the call site from the raw response, or carry it in an error `code` |
| **Testing** | `benzenetest` in-process test host (`Invoke[TReq, TRes]`) | — | — |

## Transports — HTTP, gRPC, brokers

| Area | What benzene-go provides | What it deliberately does NOT do (and why) | How to solve the rest |
|---|---|---|---|
| **HTTP inbound** | Native REST-style routing + envelope-over-HTTP (`httpbinding/`, shared dispatch in `envelope/`); portable CORS middleware (`cors/`). The envelope endpoint (`EnvelopeHandler`, `/benzene/invoke`) answers 200 for every processed envelope — `not-found`, `deleted`, a pipeline `unauthorized` alike — and 400 only for a body that is not an envelope; the inner problem omits `status`; `WithTopicFilter` restricts the topics it reaches (a restricted topic is `not-found`). A route mapped to a health topic answers 503 when the report says `isHealthy: false` (`httpstatus.Response`, shared with `awslambda.HTTPHandler`/`azurefunctions.Handler`) | Own the HTTP server — the binding is an `http.Handler` you mount; host-enforced 401/403 before the envelope is read is your `net/http` middleware's job | Mount on any `net/http`-compatible server/mux; wrap `EnvelopeHandler` in your auth middleware |
| **HTTP outbound** | `httpclient.Client` (one `Send`), satisfying `client.Sender`; decorators `WithCorrelationID`/`WithRetry` (`client/`). Reads the response envelope whatever the HTTP status, through `envelope.ToResult` (`isSuccessful` decides; a missing one is a failure), and falls back to the reverse HTTP table only when the body is not an envelope — then rebuilding the errors, field and code intact, from a problem-document body (`application/problem+json` or JSON) | Manage connection pooling/auth for you | Supply your own configured `*http.Client` |
| **gRPC** | `grpcbinding` (own module): `UnaryServerInterceptor` claiming only routed methods, proto3-JSON bridging, `benzene-status` trailer, outbound `Client`; status tables in `grpcstatus/`; `errors[].field` pointers become dotted `FieldViolation.field` paths (`/items/0/sku` → `items[0].sku`) and the client turns them back into pointers; `errors[].code` is written to `FieldViolation.reason` and read back (wire-contracts §4.2) | Streaming RPCs (client/server/duplex) — **not implemented**, a documented gap; and no codegen of service stubs — the binding claims routes, it doesn't own the server | Register real protoc-generated services; unmatched methods fall through untouched |
| **Kafka (self-hosted)** | `kafka` (own module, `segmentio/kafka-go`): consumer-group `Consumer` (one invocation + scope per record, explicit commits) + outbound `Client`; topic from the record's `topic` header (`ReservedNames`, inherited from the builder), falling back to the Kafka topic it was consumed from (transport-bindings' Kafka entry); other headers and the value verbatim; the `Client` produces to a Kafka topic named after the Benzene topic. Settlement: skip-and-continue by default (`kafka.DefaultDelivery`; a failed message goes to `OnFailure` and is committed past), or `envelope.AtLeastOnce` to re-dispatch it in place until it succeeds | Broker-side redelivery/DLQ — Kafka has none | Wire `OnFailure` to a dead-letter topic publish or log, or choose at-least-once and accept that a poison message stalls its partition |
| **RabbitMQ** | `rabbitmq` (own module, `amqp091-go`): self-hosted `Consumer` + outbound `Client` | — | — |
| **CloudEvents** | `cloudevents/` — envelope↔CloudEvents 1.0 mapping + inbound HTTP handler (both content modes), zero-dep | Ship per-broker CloudEvents transports — the mapping is the bridge; delivery is whatever CloudEvents-shaped system you point at it | Point Event Grid, Knative, EventBridge, etc. at the handler |

## Mesh, health, spec surface

| Area | What benzene-go provides | What it deliberately does NOT do (and why) | How to solve the rest |
|---|---|---|---|
| **Mesh service-side** | `mesh/` — the service registers its Contract Document, the same `contract.Derive` document `benzene:spec` serves, through `mesh.Announcer` (`announce.go`): `Registration` fills a detected `placement` (`DetectPlacement`) when the document carries none; `runtime` (`"go"`), `profile` (`cloudservice.New`'s self-check) and `degraded` (events and sends when no `OutboundRegistry` was supplied) come from the derivation; no `instanceId` in the body. Likewise a topic row's `lastSeen` is absent (not the zero time) for a declared topic with no traffic. Passes `mesh-collector-cases.json` and `mesh-issue-cases.json` | Durable storage — the collector is a diagnostic surface, not a system of record. **Service Versions is not implemented**: the catalog keys by `service` alone, so two side-by-side releases replace each other's registration, and `mesh-service-version-cases.json`/`mesh-version-order-cases.json` are listed opt-outs. The produced-vs-consumed version-skew read model is **not implemented**. Old `topics`/`produces` register bodies are not read | Any port's collector can host this port's services over the shared `benzene:mesh:*` contract; use the .NET collector for side-by-side versions |
| **Mesh View (UI)** | `meshd.ViewHandler` (`meshd/view.go`) — serves a **Go-native** embedded page (`view.html`, no JS framework, no external assets) at `/benzene/fleet-ui`, polling the collector's fleet query through the envelope endpoint. It does **not** embed or serve a canonical cross-language `mesh-ui.html` — no such asset is referenced in this repo; the page is this port's own rendering of the shared query contract | A rich SPA — zero-dependency stance extends to the page | The wire contract is the interop point; any UI can poll `benzene:mesh:query:*` |
| **Health checks** | `healthcheck/` — reserved-topic interception middleware + `TCPCheck`, `HTTPPingCheck`, `DiskSpaceCheck` (zero-dep; error *categories*, not raw messages, so internal hostnames/credentials don't leak). The result is `ok` whenever the checks ran; `isHealthy` carries the verdict (a warning does not flip it), and `GET /benzene/health` answers 503 when it is false. `RouterMiddleware` answers the reserved `benzene:ping` probe `ok` with no payload, so queue-borne probes are acknowledged. No `benzene:liveness`/`benzene:readiness` topics or routes are served | Ship dependency-specific checks (database ping, broker liveness) — a check is a one-function interface | Implement `healthcheck.Check` calling your dependency's SDK |
| **Client-side contract check** | `clienthealthcheck.ServiceCheck` — asks a provider's `benzene:spec` for its Contract Document via an outbound `Sender` and compares the **served** `contractHash` with the one supplied by `WithExpectedContractHash` (a generated client's `ContractHash`), reporting the *contract* relationship (drift = `warning`, not a health flip). No provider-side or private hash: the check computes nothing itself | Couple the check to the provider's transient health — `benzene:spec` is served health-independently on purpose, so contract drift and downtime stay distinguishable | Use `benzene:healthcheck` for liveness; this check is a contracts diagnostic |
| **Spec endpoint & profile** | Default paths per `transport-bindings.md` §1: `/benzene/invoke`, `/benzene/spec`, `/benzene/health` (`httpbinding.EnvelopePath`/`SpecPath`/`HealthPath`) and `/benzene/fleet-ui` (`meshd.ViewPath`), each configurable by mounting elsewhere; this port serves no spec-ui, mesh-ui or MCP surface. **Self-description (R5):** the `contract` package derives the Contract Document (`contract-document.md`, spec-0.4.0 shape: `schemaDialect: "openapi-3.0"`, `service`/`serviceVersion`/`versionScheme`/`description`, the deployment-side `runtime`/`placement`/`profile`/`degraded` outside both hashes, `requests`/`events`/`sends`, no `benzene:` entries, an absent `response` for a handler returning `struct{}`, author examples only — none synthesized) at start-up with `contract.Derive`, which hoists every named struct into `components` (OpenAPI 3.0 dialect: nullable pointer to a named struct is the `{"type":"object","nullable":true,"allOf":[…]}` wrapper; `format` emitted for ints, floats, times and bytes), names it by `BenzeneSchemaName()` or its Go name, and **fails before the first message** on a component-name collision (`*contract.NameCollisionError`, naming both types, the topics and the remedy); undeclared generic instances are inlined. `contract.Middleware` answers `benzene:spec` (`{type?, format?}`; anything but `benzene`/`json` is `not-implemented`; `WithDocumentType` adds port extensions such as AsyncAPI), and `httpbinding.SpecHandler` serves `GET /benzene/spec` through the pipeline, copying the `type`/`format` query parameters. Both hashes — `contractHash` and `registrationHash` — are computed in the root module (`contract.HashDocument`) over the §6.2 projection, canonicalized by the hand-written RFC 8785 `internal/jcs` (differentially fuzzed against `gowebpki/jcs` in `codegen/jcsfuzz`). Events and sends are declared with `contract.RegisterEvent`/`contract.RegisterSend` (`WithResponse` for a reply); a (topic, version) in both is a start-up error. **Cloud Service Profile (R1–R5, R7):** `cloudservice.New` — one-call builder wiring the whole profile (R5: `benzene:spec` intercepted in the pipeline, answered wherever the transport carries a reply, and `GET /benzene/spec`), returning its derivation error or an honest `ProfileReport`: `Requirements` is the R1–R5/R7 checklist (`Satisfied()`/`Unsatisfied()`), which the document carries as its `profile` (`{"name":"cloud-service"}`, `missing` listing only R1–R5/R7 ids and omitted when none), and `Mesh` reports the meshed-service claim's M1/M2 apart (`Meshed()` requires the profile too); no Go consumer reads `profile.missing`, so a stale `R6`/`R8` from an older service is ignored. `cloudserviceprobe.Run` — external black-box probe with tri-state verdicts for R1–R5/R7 (R5 needs both `GET /benzene/spec` and `benzene:spec` over the envelope endpoint), with `Report.Mesh` carrying M1/M2 as always `Inconclusive` (not observable from one service), noting any profile requirement observed unmet. A bodiless request on any `Route` mapped to `benzene:spec` — through `httpbinding.Handler`, `awslambda.HTTPHandler` or `azurefunctions.Handler` — carries its `type`/`format` query parameters as the request, as `httpbinding.SpecHandler` does | `cloudservice.New` does not wire the meshed-service claim — M1's three feeds (registration, heartbeats, traces) or M2 (trace propagation) — they need a collector and exporter lifecycle the app owns; the report's `Mesh` section says so rather than overclaiming. The probe keeps its own path constants — it must audit *any* port's service, so it deliberately duplicates rather than imports | `Report.Mesh.Unsatisfied()` is the exact to-do list to become meshed; run a `mesh.Announcer` over `Service.Contract`, wire `mesh.TraceMiddleware` and the push exporters, and wrap every outbound `Sender` (the event publisher's included) in `mesh.WithTraceContext` yourself |
| **Contract docs & codegen** | `openapi/` — OpenAPI 3.0 generation from the Contract Document (its components and `$ref`s carried over as they are); `asyncapi/` — AsyncAPI 3.0 generation from the Contract Document (requests → `receive`, with a reply only when a response is declared; events and sends → `send`), each with a GET `Handler`; `codegen` (own module: `contractdoc` + `gengo` + `cmd/benzene-codegen`) — typed-client generation from a Contract Document: rejects an unknown `schemaDialect`, ignores `benzene:` entries, include-list and topic-scoped projections recompute both hashes with the root module's `contract.HashDocument`, an absent response generates `Result[struct{}]`, and the nullable wrapper becomes a pointer field. Passes every `parseCases`/`topicScopeCases`/`schemaClosureCases` case and every `contract-hash-cases.json` case, projections included | Infer events or sends from call sites — they come only from `RegisterEvent`/`RegisterSend` declarations. Deriving `responseevents` mappings into event declarations is **not implemented**. Typed enums: Go cannot list a named string type's values, so enums derive as their base type | Declare each event with `contract.RegisterEvent`; see `docs/codegen-client.md` for the client pipeline |

## Cross-cutting building blocks

| Area | What benzene-go provides | What it deliberately does NOT do (and why) | How to solve the rest |
|---|---|---|---|
| **Idempotency** | `idempotency/` — atomic-claim middleware over a pluggable `Store`; `InMemoryStore` (single-process, TTL); store outage fails open; a failure is never permanently suppressed | Cross-instance de-duplication — independent processes can't coordinate without external shared state, and shared state can relocate the race, not remove it | An external store with an atomic conditional write (DynamoDB conditional put, Redis `SET NX`) behind the `Store` interface, plus naturally idempotent handlers |
| **Settlement (one-way bindings)** | Every one-way binding settles through `envelope.Settlement` (`envelope/settlement.go`), taken as `WithSettlement` by the handler constructors and as a `Settlement` field by the self-hosted workers. Its zero value is the spec default (transport-bindings §1, obligation 8): a message is acknowledged only when its invocation's `isSuccessful` is true (`ignored` included); a failure result, **no result** (`unexpected-error`), an **unmatched topic** (`not-found`), a middleware's Go error and a recovered handler panic are all redelivered — except the self-hosted `kafka.Consumer`, a stream that documents skip-and-continue as its default. Every binding offers the at-most-once override (`envelope.AtMostOnce`) and unmatched-topic-as-ignored (`IgnoreUnmatchedTopics`, keyed on `benzene.IsUnmatchedTopic`). Asserted against `settlementDefaults` by `conformance/settlement_conformance_test.go`. See the [per-binding breakdown](#settlement--the-per-binding-breakdown) | A single cross-transport acknowledgement abstraction — each binding settles with its transport's own signal (batch-item failure, Go error, non-2xx, nack, abandon, withheld delete/commit/checkpoint) | Make handlers idempotent (`idempotency/`). Bound retries with the transport's redrive/DLQ settings |
| **Outbox** | **Not implemented.** Nothing ships; the only trace is a seam — `responseevents.Publisher` is documented as implementable by "an outbox relay" (`responseevents/responseevents.go`). This is an unbuilt gap, not a design decision: the .NET reference ships `Benzene.Outbox`, and this port's ROADMAP records no "no" for it | — | Store-and-forward in your handler's own transaction against your store, relaying via a `client.Sender`; pair the consuming side with `idempotency` |
| **Oversized payloads (claim check)** | **Not implemented.** No package, no seam. An unbuilt gap, not a design decision — the .NET reference ships `Benzene.ClaimCheck` | — | Offload to blob storage in a small middleware pair (offload before send, hydrate before deserialize), carrying the reference in a header |

## Settlement — the per-binding breakdown

Re-audited against the source on 2026-10-11, after the spec-0.2.0 settlement work. "Failure" means
the invocation ended with `isSuccessful: false` (`validation-error`, `not-found`, …), with no result
(reported as `unexpected-error`), or with a middleware's Go error (`service-unavailable`). Every row
inherits these facts:

- Every one-way binding settles through `envelope.Settlement` (`envelope/settlement.go`), whose
  `Outcome.Acknowledge` is true for a successful invocation, for any outcome under
  `envelope.AtMostOnce`, and for an unmatched topic under `IgnoreUnmatchedTopics`. So the *no
  result* and *unmatched topic* columns always match the *failure* column unless a knob says
  otherwise.
- `RouterMiddleware` (`router.go`) always sets a result: an unmatched topic is `not-found` (marked so
  `benzene.IsUnmatchedTopic` can tell it from a handler's own `not-found` or an unknown version), an
  empty topic is `validation-error`, a handler panic is recovered as `service-unavailable`, and the
  reserved `benzene:ping` probe is `ok` — so queue-borne health probes are acknowledged.
- `Pipeline.Run` (`middleware.go`) does **not** recover a panic in a middleware outside the router.
  The *uncaught panic* column records where that panic lands; no knob applies to it.
- `redeliver` means the binding withholds acknowledgement, so the transport's own redelivery applies.
  Retry counts and dead-lettering are the transport's redrive configuration, not Benzene's.
- **Knobs** on every row: `envelope.AtMostOnce` (acknowledge whatever the outcome) and
  `IgnoreUnmatchedTopics`; the failure hook, where a binding has one, still sees every failure.

### Divergences from the .NET settlement contract

- **Unmatched topic on `awskafka` (MSK) and the Functions Event Hub trigger.** .NET acknowledges an
  unrouted (no-result) outcome on these. Here the router always sets `not-found`, so they redeliver
  by default — `IgnoreUnmatchedTopics` is the opt-in for .NET's behaviour.
- **Self-hosted Event Hub (`azureeventhub.Consumer`).** .NET defaults to at-most-once
  (catch-and-continue). This consumer defaults to at-least-once and redelivers a failed event in
  place; `envelope.AtMostOnce` matches .NET.
- **Cosmos DB change feed (`CosmosHandler`, `azurecosmos.Worker`).** In .NET a returned result does
  not apply (fan-in, with no result; only a throw redelivers). Here the batch is one result-bearing
  invocation, so a failure result redelivers the whole batch; `envelope.AtMostOnce` matches .NET's
  `CatchHandlerExceptions = true`.
- **Kinesis (`awskinesis`).** .NET is fan-in with handler-driven checkpoints. Here each record is
  routed by stream name and processing stops at the first failure. Both redeliver; the unit differs.
- **Middleware panic on a self-hosted worker.** .NET's Service Bus and RabbitMQ workers abandon or
  nack a throwing message and carry on. Here the panic escapes `Run`; the in-flight message is
  redelivered by the broker, or from the uncommitted position after a restart.

## Deliberately out of scope (a "no", not a gap)

.NET-ecosystem idioms with no Go analogue to port (see `ROADMAP.md` for the full reasoning):
alternate DI containers (`Container`/`Scope` is the Go idiom), alternate loggers (`log/slog` is
standard), alternate serializers (`encoding/json` is idiomatic; Avro/MessagePack would be new
dependency decisions, not ports), vendor-specific observability packages (OTLP covers them), and
ASP.NET-on-Lambda/Functions hosting bridges (`net/http` handlers *are* the pipeline here).

## Why "we don't do that" is a feature

Every deliberate "no" above buys you something: you keep the full power of the tool you chose,
you're never blocked by a leaky abstraction, and the zero-dependency core stays small and stable.
When you need something benzene-go doesn't ship, the extension model — a custom `Middleware`, a
custom `Check`, a `Store`/`Limiter`/`Sender` implementation — is the supported, documented path.
See `docs/middleware.md`.
